# Scoutvy

An Android-first bounty app for online and on-location tasks. Posters set the requirements and fund the full reward into Solana escrow; accepted work receives the reward through the escrow program. Written submissions and camera/location proof are supported.

The current application and API use **Solana Devnet**. These builds are for verification, not a mainnet or store launch.

## Stack

- Expo SDK 57, React Native 0.86, Expo Router, shared Phantom-inspired dark UI.
- Mobile Wallet Adapter for wallet authentication and transaction approval.
- Vercel API, Neon Postgres, Solana escrow in `escrow/`.
- MapLibre maps. Expo Push with Firebase used only for Android FCM delivery.

## Run locally

Use the committed lockfiles and an installed Android SDK/JDK:

```sh
npm ci
npm --prefix server ci
npm run android
```

Wallet/native integrations require an Android development or release build; Expo Go is insufficient. `npm start` starts Metro for an installed development build. Native folders are generated by Expo; put persistent native changes in `app.json` or `plugins/`.

The client defaults to the deployed Devnet API at `https://scoutvy.vercel.app`. Optional local overrides are `EXPO_PUBLIC_API_URL` and `EXPO_PUBLIC_SOLANA_RPC_URL`; never put private credentials in public environment variables.

## Android builds

For the existing emulator installation, preserve its debug signing identity and data:

```sh
npm run android:device-build
adb install -r artifacts/android/scoutvy-device.apk
```

For a separately signed Devnet candidate:

```sh
# Only needed on a new machine without restored signing credentials.
npm run android:signing-setup
npm run android:distribution-build
```

Outputs are `artifacts/android/scoutvy-devnet-signed.apk`, `.aab`, and a JSON record of certificate/file SHA-256 hashes. Local scripts build ARM64 only, verify APK signing, and verify AAB integrity. They do not install, upload, or publish the candidate. Do not replace the existing debug-signed installation with the distribution APK: Android requires matching signing certificates for an update. Never uninstall a wallet or clear its data to resolve signing errors.

Local release signing reads root `credentials.json` and `credentials/scoutvy-android-upload.jks`. Both are ignored and owner-only. Keep an encrypted backup of **both files together**, outside this checkout; neither Git nor the build script backs them up. The setup script preserves existing credentials. The escrow authority is a separate key and must not be used for Android signing.

EAS profiles also use local credentials; no EAS-hosted Android keystore is assumed. Prefer the local scripts to preserve cloud-build quota. The `production` profile creates an app bundle but does **not** change the app from Devnet to mainnet. iOS is not release-verified.

## Backend and database

`server/` is the Vercel project root. Server secrets belong in Vercel or an ignored local environment: database connection, attester key, cron secret, and optional push access token. Never commit or print their values.

```sh
# DATABASE_URL must already be provided securely to this process.
npm --prefix server run db:migrate
npm --prefix server run typecheck
```

Migrations include generalized bounties and financial-history-safe account deletion. Account deletion removes private profile/session/device data while retaining shared submissions and escrow receipts. It never transfers or refunds funds. Existing financial history must not regain cascading user foreign keys.

Reports are reviewed through the authenticated operator CLI described in `AGENTS.md`. Notification events send immediately; the daily maintenance cron is recovery, not a rapid-delivery guarantee.

## Verification and release boundaries

```sh
npm run lint
npm run typecheck
npm --prefix server run typecheck
```

Real Devnet funding, cancellation/refund, written submission/protection/payout, Android wallet payout, push delivery, and account deletion have recorded evidence in the sibling `scoutvy-ui-audit/refinement/` directory. Consult `AGENTS.md` for transaction IDs and exact scope before retrying financial operations.

Physical camera/GPS behavior still needs a device check. Solflare reputation approval is external; a valid domain association does not guarantee it. A public release also needs store signing/ownership setup, mainnet readiness, and a hosting plan compatible with commercial use. Do not enable billing or deploy mainnet automatically. See `escrow/README.md` for contract details.
